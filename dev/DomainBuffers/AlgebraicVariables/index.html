Algebraic variables

Experimental

The support for algebraic variables is experimental. The functions described on this page are not yet part of the public API, and may change without being considered a breaking change.

Ferrite's algebraic variables (AlgebraicVariable) are global unknowns that are not associated with the grid, for example a Lagrange multiplier that enforces the mean value of a field, a cavity pressure, or the load factor in a path-following method. Their degrees of freedom are not part of celldofs. To use them in the element or facet routines, they are given to the DomainSpec for the domains that use them,

dh = DofHandler(grid)
add!(dh, :u, ip)
add!(dh, :λ, AlgebraicVariable())
close!(dh)
domain = DomainSpec(dh, material, cellvalues; algebraic_per_cell = (:λ,))

The same keyword is used for facet domains, and the same variable can be used in several domains, including both cell and facet domains. The contributions from the different domains are then added during assembly. See Mean value constraints for a complete example.

Local degrees of freedom

For each item (cell or facet) in a domain with algebraic variables, the degrees of freedom of each variable in algebraic_per_cell are added after the cell's degrees of freedom, in the given order. Consequently, the following have the size of, and are ordered according to, these local degrees of freedom:

  • ae and get_aeold(buffer), including the current and old values of the algebraic variables
  • re and Ke, including the contributions to the equations for the algebraic variables
  • celldofs(buffer), including the global degrees of freedom of the algebraic variables

The local dof range for each field is not changed, and dof_range(buffer, name) also gives the range for an algebraic variable with name name. Since ae contains more values than the number of shape functions, the element routine must pass the dof range when evaluating a field, e.g. function_value(cellvalues, q_point, ae, dof_range(buffer, :u)). The value of an algebraic variable is obtained as

av = FerriteAssembly.get_algebraic_values(buffer, :λ)
λ = algebraic_value(av, ae, dof_range(buffer, :λ))

which, e.g., gives a tensor for an AlgebraicVariable{SymmetricTensor{2, 3}}. Ferrite.getfieldnames(buffer) and the dofrange given to create_cell_state contain the fields, followed by the algebraic variables.

FerriteAssembly.get_algebraic_values — Function
get_algebraic_values(itembuffer::AbstractItemBuffer, name::Symbol)

Get the Ferrite.AlgebraicValues for the algebraic variable name, which must be one of the variables given as algebraic_per_cell to the DomainSpec. Together with dof_range(itembuffer, name), the value of the variable is then algebraic_value(get_algebraic_values(itembuffer, name), ae, dof_range(itembuffer, name)).

Sparsity pattern

The entries for the algebraic variables are not included in the default sparsity pattern. The required coupling information for the domains is created by

FerriteAssembly.algebraic_couplings — Function
algebraic_couplings(buffers...)

Create a Vector of coupling descriptors for the domains with algebraic variables (see the algebraic_per_cell keyword of DomainSpec) in buffers. Each element in buffers can be a domain buffer, a DomainBuffers, or a Simulation. The output can be passed to Ferrite's allocate_matrix, to allocate the entries required for the algebraic variables in the sparsity pattern, i.e.

algebraic_couplings = FerriteAssembly.algebraic_couplings(cellbuffers, facetbuffers)
K = allocate_matrix(dh, ch; algebraic_couplings)

For each domain, all fields in the domain are coupled to all algebraic variables in the domain, and all algebraic variables in the domain are coupled to each other. If this gives too many entries in the sparsity pattern, the coupling descriptors can instead be created manually. If more coupling entries are desired, they can be push!ed to algebraic_couplings.

source

Ferrite's allocate_matrix also accounts for constraints, e.g. affine constraints where the degrees of freedom of an algebraic variable are the masters. Constraining the degrees of freedom of algebraic variables is done with AffineConstraints, and these can be applied both locally (with a ConstraintHandler given to the KeReAssembler) and to the global system after assembly. A degree of freedom that doesn't get any contributions, e.g. a component of a tensorial variable that isn't used in any element, must be constrained to avoid a singular system matrix.

Multithreading

Multithreaded assembly of domains with algebraic variables requires an atomic assembler, e.g. KeReAssembler(K, r; atomic = true). Otherwise, such domains are assembled sequentially.

Further details

  • Automatic differentiation: Defining only element_residual! works as for other cell domains, and the stiffness then includes the coupling to the algebraic variables. There is no automatic differentiation for facet domains.
  • Renumbering: The global degrees of freedom of the algebraic variables are updated once when starting to work a domain, such that renumbering the dofhandler after setting up the domain buffer is supported.
  • Residual scaling: ElementResidualScaling calculates one factor for each algebraic variable, in addition to the factor for each field.
  • Workers evaluating fields: The SimpleIntegrator and QuadPointEvaluator pass the values and gradients of the fields. The values of the algebraic variables are not passed.
  • Loads: The contributions added by the LoadHandler cannot depend on algebraic variables. Such contributions can be implemented with facet_routine! or element_routine!.
  • Coupled simulations: A coupled buffer, see get_coupled_buffer, gives access to the algebraic variables of the coupled simulation in the same way as for the buffer itself.
